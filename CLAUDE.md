# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Agent MCR (Agent Mission Control Room) is a local harness for coding-agent sessions, built on MDViewer. The harness architecture, its signed decisions and the delivery sequence are in `docs/AGENT_HARNESS_DESIGN.md`. Read it before changing harness code. `upstream` is `lambda-house/mdviewer-mj`; viewer fixes are merged from there.

MDViewer is a cross-platform markdown document viewer built with Tauri 2.0, React 18, and TypeScript. It renders markdown with Shiki syntax highlighting, Mermaid diagram support, and features a tabbed multi-document interface.

## Build Commands

```bash
npm install              # Install dependencies
npm run dev              # Start Vite dev server (port 1420)
npm run tauri dev        # Run full Tauri desktop app in dev mode
npm run build            # TypeScript check + Vite build
npm test                 # Frontend unit tests (Vitest)
npm run build:app        # Build Agent MCR.app (release, ad-hoc signed)
```

Frontend unit tests are Vitest files next to the code (`src/utils/*.test.ts`; DOM tests declare `// @vitest-environment happy-dom`). There is no linter. The Rust backend has unit tests: `cd src-tauri && cargo test`.

## Architecture

### Frontend (src/)

- **State Management**: Zustand store in `src/store/index.ts` manages all app state with localStorage persistence
  - Key constants: `MAX_RECENT_CLOSED = 10`, `MIN_ZOOM = 50`, `MAX_ZOOM = 1600` (no tab limit)
  - State includes: file tree, documents/tabs, UI panels, zoom level (document `zoom` plus per-panel `panelZoom`)

- **Components** (`src/components/`):
  - `App.tsx` - Main shell; its key handler runs the commands of `utils/commands.ts`
  - `MainMenu.tsx` - Toolbar menu (top left): every command, grouped, with its shortcut
  - `FilePanel.tsx` - Left sidebar file tree browser
  - `DocumentPanel.tsx` - Center markdown renderer with ErrorBoundary. Scroll positions per document are anchored to the block at the top of the view (`utils/scrollAnchor.ts`), so late Mermaid output doesn't move the restored text
  - `TabBar.tsx` - Tab strip: preview tab, context menu, back/forward, overflow scrolling
  - `TocSidebar.tsx` - Right sidebar table of contents
  - `AgentPanel.tsx` - Agent workspace panel (shares the left slot with search and history)
  - `FindBar.tsx` - Ctrl+F find in document (CSS Custom Highlight API; highlights are changed in place, WebKitGTK doesn't repaint replaced ones). A jump and the scroll restore both use `utils/scrollHold.ts` to keep their offset while late output changes the layout
  - `SearchPanel.tsx` - Ctrl+Shift+F text search in open tabs / folders
  - `Editor.tsx` - CodeMirror 6 source editor (Ctrl+E), lazy-loaded; per-document state lives in `utils/editorRegistry.ts`, saving in `utils/save.ts`
  - `WorkspaceMenu.tsx` - Saved workspaces (folders + tabs)
  - `Toolbar.tsx` - Top bar with search, zoom, theme controls
  - `ConfirmDialog.tsx` - Modal question; buttons in the platform's order (`utils/platform.ts`). `SaveAllDialog.tsx` uses it
  - `Resizer.tsx` - Panel separators: drag to resize, drag to the edge or double-click to hide/show
  - `StatusBar.tsx` - Bottom status bar (auto-hides)

- **Hooks** (`src/hooks/`): `useSmoothWheelScroll` - velocity-based wheel scrolling shared by the document, file panel and TOC

- **Commands** (`src/utils/commands.ts`): `buildMenu` is the one list of commands (label, shortcut, `enabled`/`checked`, `run`). The menu renders it and the key handler in `App.tsx` matches key presses against it, so a new command or shortcut goes there, not into either of them. `run` must be safe when `enabled` is false (shortcuts don't check it)

- **Markdown Processing** (`src/utils/markdown.ts`):
  - markdown-it with `html: false` (raw HTML is escaped; every custom renderer rule must escape what it emits with `escapeHtml`)
  - Shiki for syntax highlighting (15+ languages)
  - Mermaid for diagrams with unique ID generation per render
  - HeadingIdGenerator for automatic anchor links
  - `renderFile` dispatches by type (`getFileKind` in `utils/files.ts`): markdown, fb2 (converted via `utils/fb2.ts`), code (one highlighted fence), plain text
  - Block elements carry `data-line` (0-based source line, frontmatter included) to map search results to the rendered DOM

### Backend (src-tauri/)

Rust backend provides Tauri commands:
- `scan_directories` - Recursive file discovery (markdown, plus other text files with `includeTextFiles`; extension lists mirrored in `utils/files.ts`)
- `read_file` / `write_file` - File I/O; `read_file` decodes UTF-16 BOM and XML-declared encodings, `write_file` encodes back the same way (refuses unknown encodings) and replaces the file atomically (temp file + rename, `atomic_write`)
- `pick_directory` / `pick_files` / `export_file` - Native folder picker, file picker (Open File) and save dialog, opened from Rust (the JS dialog plugin isn't exposed)
- `get_file_info` - File metadata
- `start_watching` / `stop_watching` - File system watching (one event per change; `node_modules`/`target`/`.git` ignored). The frontend debounces rescans (300ms, no overlapping scans), `setFiles` reuses unchanged tree nodes, and open documents whose file name changed are reloaded unless dirty (`reloadChangedDocuments` in `App.tsx`)
- `read_history` / `append_to_history` / `clear_history` - `history/history.md` in the config dir, capped at 1000 entries, writes serialized
- `adopt_session_access` - One-time migration of a session saved before the access list existed
- `open_external` - Opens http/https/mailto links in the default browser (opener plugin, Rust-side only)
- `localfile://` protocol - Serves images referenced by documents (`convertFileSrc(path, 'localfile')` in the frontend)

Security: an allowlist (`Access` / `AccessState` in main.rs, persisted to `access.json` in the config dir). Paths are added only from Rust on user actions: the folder and file pickers, drag & drop (`on_window_event`), command-line / single-instance launch paths. Every command resolves its path to a `Target` (as named, and canonicalized with `dunce`) and checks it with `AccessState::check(target, Use::...)`: documents need to be an opened file or a viewable file inside an opened folder, listing/watching needs an opened folder, `localfile://` serves only images. A symlink inside an opened folder passes when its real target fits the use (`Use::fits_target`); paths with `..` only count as their real location. Never grant access to an arbitrary path passed from the webview. `follow_local_link` grants after the user confirms a native dialog; session memory opening grants only a Markdown file revalidated against the backend memory catalog under separate session and memory consent. 10MB limit for documents, 50MB for images. CSP in `tauri.conf.json`. A navigation guard plugin (`navigation_guard`) blocks any navigation away from the app's own pages; document link clicks are handled in `App.tsx` (anchors, `openExternal`, local files via `followLocalLink` then `openPath`). Updates: `tauri-plugin-updater`, Rust-only (`check_for_update`, `install_update`); the frontend shows `UpdateBanner` and blocks installing while tabs are dirty. Agent MCR has no release channel yet: `RELEASE_CHANNEL` in main.rs is false, so `check_for_update` offers nothing, and `bundle.createUpdaterArtifacts` is off. Remote images render as `span.remote-image` placeholders; `MarkdownViewer` swaps them in with `loadRemoteImages` when the `loadRemoteImages` setting or the per-document "Load images" allows it. Agent workspace (`src-tauri/src/agent.rs`, `AgentPanel.tsx`, `utils/agent.ts`): turned on by `enable_agent_workspace` after a native dialog, stored as `agent_workspace` in `access.json`. While on, `Access::can_open`/`can_stat` also allow `agent::is_agent_document` (markdown in fixed places under `~/.claude`, `~/.codex`, `~/.gemini`; extend `classify_rel` and its test together). Markdown includes Cursor's `.mdc` and `.cursorrules` (`is_markdown_file` / `isMarkdownFile`). `agent::Watch` (started by the `agent_workspace` scan, re-armed on every scan) emits `agent-files-changed`; the frontend debounces it and polls only when `watching` is false. `agent_workspace` scans those plus agent files in opened folders; `mark_read` / `read_snapshot` keep a copy per file in `read-state/` for the "changed since you read it" highlight (`diffContent` + `markChangedBlocks` on `data-line` blocks). Capabilities (`capabilities/default.json`) allow core defaults and window destruction for `main` and `memory-*` readers.

Tests: `cargo test` in `src-tauri` (unit tests at the bottom of main.rs and agent.rs). CI runs clippy, the Rust tests and `npm test`.

### Agent harness (docs/AGENT_HARNESS_DESIGN.md)

`runner.rs` is `agent-mcr --runner` (branches in `main` before Tauri starts): it owns agent PTYs (`portable-pty`), a 4 MB scrollback per session and exit codes, on `runner.sock` in the config dir. It has no policy, MCP or SQLite. Its JSON-lines protocol is versioned (`PROTOCOL`): change it only additively, because the app speaks N−1. `ensure` starts it through the LaunchAgent `cc.lambdahouse.agent-mcr.runner` (plist in `~/Library/LaunchAgents`, rewritten when the executable changes), so agents outlive the app. It exits after 10 idle minutes with nothing running. `attach` streams raw bytes (scrollback, then live). `watch` streams events, including BEL and OSC 0/2/9/777 found by `Scanner`. `harness_commands.rs` is the app side: the webview only picks a `PROFILES` id (run as `$login_shell -l -i -c 'exec …'`, D7 permission modes) and a folder it opened, a session directory or home. Output reaches the webview over a raw `Channel`. Pasted images go to `~/Library/Caches/agent-mcr/attachments`. Frontend: `LiveWorkspace.tsx` (the Live view in Sessions), `TerminalPane.tsx` (xterm.js) and `utils/harness.ts`. Local builds are the gate (D12).

`harness.rs` is the harness service, `agent-mcr --harness` on `harness.sock` (LaunchAgent `cc.lambdahouse.agent-mcr.harness`, same `runner::Unit` start as the runner). It creates sessions (`create`: profile or `resume`), tracks their state, queues tasks and serves the supervisor MCP; `harness-state.json` is its store (SQLite comes with messaging). State comes from the agents' own hooks, passed per launch and never written to the user's agent config: Claude gets `--settings claude-hooks.json` (SessionStart, UserPromptSubmit, PostToolUse, Notification, Stop) and `--session-id`; Codex gets `-c notify=…`. Both call `agent-mcr --harness-hook <event>`, which must stay silent and always succeed. `apply_hook` is the pure state machine: test changes there. Three things no hook reports are handled separately, and each was found by a live run: Claude's start-up questions (`stalled`: quiet and no hook yet → attention), Codex turn ends of other threads (title writer, subagents: only the session's own `thread-id` counts; `hook` asks the transcripts through `top_level_thread` which thread is the person's, because a subagent's turn end taken as the session's leaves it `working` for good and no inbox notice is ever typed), and Codex before its first turn end (a task is typed only when `codex_at_prompt` sees the input box, otherwise it would answer whatever is on screen). Tasks are typed as a bracketed paste plus Enter when the session is idle, one at a time; the first task goes in argv. `--supervise` bridges stdio to the supervisor MCP (`supervisor_tools`, root per D5). D6 is enforced in `tool`: `task_assign`, `terminal_write` and `session_interrupt` are refused while a session's attention is `permission`. `terminal_read` renders the runner's `snapshot` through `vt100`. `resumable` / `find_resumable` read only ids, folders and times from transcript heads; a resume id must match an existing transcript. The app lists and creates sessions through the service and keeps terminal bytes on the runner.

Harness tools between sessions (agent agnostic): every Claude and Codex launch also gets the `mcr` MCP server (`agent-mcr --harness-mcp`; Claude via `--mcp-config claude-mcp.json` and a `mcp__mcr` allow rule in the per-launch settings, Codex via `-c mcp_servers.mcr.*`). Tools in `agent_tools` / `agent_tool`: `whoami`, `list_peers`, `send_message`, `ask`, `reply`, `read_inbox`, `listen`, `set_status`. The caller is never trusted to say who it is: `caller` takes the socket's peer pid from the kernel and walks parent pids up to a runner child; anything else gets a server whose tools refuse. Messages live in the store (`Message`, kept for the operator; `messages_list` on the supervisor MCP). Delivery is `nudge`: when the receiver is idle, a fixed notice without the message body is typed into its terminal and the agent calls `read_inbox`; never into a shell, and never while a session waits on a prompt (state `waiting` is not idle). A Stop while a peer still owes a reply to an `ask` leaves the session's task open (`Store::awaiting`); a peer that exits leaves a harness notice instead (`Store::abandon`). `MAX_SENT` per ten minutes stops answer loops. Awareness: every Claude and Codex launch is told about its peers with the same text. `PEER_NOTE` (short) goes into Claude's `--append-system-prompt`, Codex's `-c developer_instructions=` (skipped when the operator's own `config.toml` sets that key) and the `mcr` server's MCP instructions; it must hold no quotes, as it is put into a shell word and a TOML string. `PEER_GUIDE` (the working rules) is served twice: as the Claude skill `agent-mcr:peers` from `<config dir>/claude-plugin`, loaded with `--plugin-dir` for the launch only, and as the `guide` tool for every agent kind. A resumed Claude conversation keeps its recorded system prompt, so there the note arrives through the MCP instructions and the skill. Sessions without the MCP tools: `Tracked.tools` is set when a session's `mcr` bridge first connects. For a session without it (started before the tools existed, or an agent that takes no MCP servers) `nudge` types a notice that gives the command form instead: `agent-mcr --harness-tool <name> [json]` (`tool_cli`), the same tools with the same `caller` identity check, printing JSON. Names: a session nobody named goes by the title its agent set in the terminal (`title_name`: without the status glyph and Codex's ` | folder` suffix; empty when it is only the agent's or folder's name). `sessions` keeps it in `Tracked.title` and reports it as `harness.name` with `named: false`, so the list, `list_peers`, addressing by name and message senders agree. `AgentMark.tsx` draws the agent kind as a small mark (simplified, not the vendors' artwork). The supervisor is not a list row: it has its own tile above the form. Supervisor session: the `supervisor` control op (app command `harness_supervisor`, the button at the top of the Live list) returns the running session with `meta.role = supervisor` or starts one: Claude in `<config dir>/supervisor`, with `claude-supervisor-mcp.json` (the `mcr` and `supervisor` servers) and `claude-supervisor-hooks.json` (both allowed without prompts, D5). The role can't be set through `create` or `session_create`. `supervise` refuses hosted sessions that are not the supervisor (`caller`), so a worker can't take over the harness; agents outside the harness keep the tools. D6 still holds for the supervisor session. The first start asks whether to trust the folder; only the person answers. Subagents: `subagents` lists a Claude session's subagents from the files next to its transcript (`<session id>/subagents/agent-<id>.jsonl` and `.meta.json`), reading only the meta file and modification times, never transcript text, and only under `~/.claude/projects`. `sessions` attaches those active in the last hour; the Live list shows them as rows under the session, marked active when written to in the last 90 s (file activity, not verified liveness). `subagent_finished` looks at the last transcript record only (a final assistant message, or the report acknowledgement, whose wording depends on the Claude Code version); finished ones are counted in one line, not listed. Codex subagents are not listed. Bridges: `--harness-mcp` and `--supervise` go through `bridge`, which outlives a service restart (every rebuild restarts it): it reconnects, replays the client's `initialize` and `notifications/initialized` without passing the second answer on, and answers the calls that were in flight with an error. A plain pipe here makes every running agent drop the server for good. Terminal size: `TerminalPane` fits only after the pane's size has been still for `RESIZE_SETTLE_MS`, because each new size makes Claude Code and Codex repaint their whole transcript. Live list: a row is the state dot, the agent mark, name and folder; a second line appears only for tasks, unread messages, a prompt or the agent's own status. Pid, command and state text are in the tooltip. Idle and ended rows are dimmed. Each row has one action menu (`RowMenu`): Copy reference (`sessionReference`, text to paste into another session) and Close session, which hangs the session up and forgets it once it has ended (`closing`); there is no interrupt button. `sessions` reports `peers` (`Store::talked_with`: live sessions with a message either way in the last day) and `groupSessions` draws sessions linked by messages or by running in the same folder as one bordered group. Each terminal pane is headed by the name its session has in the list (`.hs-pane-title`). Finished subagents are not shown. `Tracked.tools` follows the connected bridges (`Store.bridges`, reset when the service starts), so a session whose bridge is gone gets the command form in notices. Agent adapters: `agents.rs` holds one `Adapter` per agent program (`Claude`, `Codex`, `Shell`) and everything specific to it: the command line for a launch and a resume, the files a launch reads (`files`, written before every launch), whether the harness names the conversation, how it reports (`reports_from_start`, `silent_until_first_turn`, `at_prompt`), how a turn is stopped (`interrupt`), whether the peers note fits (`takes_note`) and where its transcripts are. `harness.rs` asks `adapter(profile)` and must not compare profile names; an unknown profile is a shell. A new agent is a new adapter plus a `PROFILES` entry. Restart: the `restart` control op (app command `harness_restart`, the row menu, supervisor tool `session_restart`) hangs the agent up, waits for the exit and starts a new process that resumes the same conversation (`Tracked.agent_session`, only if `find_resumable` finds its transcript; otherwise a fresh start in the same folder, `resumed: false`). The session id changes: name, role, queued tasks, messages and status move to the new one and the old row is forgotten. `Store.restarting` keeps the exit from failing queued tasks or telling askers the peer left. The tool refuses in the middle of a turn without `force`; the menu forces. It must answer within the control client's ten seconds. Usage pane: the Usage button in a terminal's title opens `SessionStats.tsx` beside the terminal (open or closed is kept in localStorage). It asks `session_stats` (same grant as the Sessions workspace, no transcript text) for the session whose id is the hosted session's `agentSession`; figures are never self-reported by agents. `sessions::Context` is filled by the same parser as usage (`PARSER_VERSION` 4): `now`/`first`/`peak` are the input side of a model response (Claude: main chain only; Codex: `last_token_usage`, with `model_context_window` as `window`), `compactions`, `tool_bytes` (bytes each tool returned, matched by call id through `Indexed.calls`) and `skills` (explicit invocations only). Tool output is shown in bytes because transcripts record no tokens per tool; do not convert it to tokens. Not built yet: MCP Tasks for `ask`/`listen` (both are plain tool calls), groups (D9: peers are all sessions), `declare_dependency`, a messages view in the app.

### Sessions workspace

`SessionWorkspace.tsx` is entered from the toolbar. `utils/sessions.ts` defines its IPC contract and pure accounting/search helpers. `src-tauri/src/sessions.rs` is the incremental Codex/Claude JSONL index, backed by `session_db.rs` (SQLx SQLite) and versioned checkpoints plus paged events. All database work runs on blocking workers. Checkpoints and events commit atomically; usage deduplication survives restart. Do not discard history when directory enumeration fails. `session_memory.rs` discovers fixed memory locations and revalidates each read; `Access.session_memories` is a separate native grant. Human forks are not child agents. Directory history, role and last-activity filters are defined in `utils/sessions.ts`; `session_commands.rs` holds the opt-in access gate, read-only remote contexts and existing-daemon Codex controls. `Access.session_workspace` is independent of `agent_workspace`. Do not grant general document reads for transcripts. Keep credentials in process memory, never in the Zustand store or exports. Usage records must be deduplicated; cache/reasoning are subsets of input/output, not extra totals. Summaries exclude activity bodies, and details load on selection. Status inferred from files must not be presented as verified process liveness. Tests cover parser accounting, partial/truncated files, hierarchy and the UI access/control paths. `examples/session_snapshot.rs` extracts real local metadata using the same index.

Memory reader windows use a validated `memoryDocument` URL and isolated, read-only inherited preferences. They do not overwrite the main workspace, own its watchers or consume its launch paths. Native menu events target the focused window.

### Session analysis MCP

`session_analysis.rs` is the bounded read-only query layer; `session_mcp.rs` implements MCP lifecycle, the app-owned Unix socket and the `--mcp` stdio bridge. The bridge branch in `main` must run before AppKit/Tauri initialization and never open SQLite. `session_analysis_commands.rs` owns the per-process native-confirmed grant and background ingestion using the same `SessionState.index` as the UI. Revocation closes connected sockets; keep grant→index lock order. `SessionAgentAccess.tsx` shows scope, clients, query audit and evidence navigation. Never infer inner exec execution, skill success, historical definition versions or per-tool tokens from references. `examples/analysis_host.rs` and `scripts/validate-session-mcp.mjs` exercise the production query/transport with the official MCP client SDK and explicit fixture paths. See `docs/SESSION_ANALYSIS_MCP.md` for semantics and remaining limits.

### Path Alias

TypeScript path alias `@/*` maps to `src/*` (configured in tsconfig.json and vite.config.ts).

## Configuration

There is no config file. UI settings, folders, tabs and workspaces live in localStorage (Zustand persist). The backend's config dir (`dirs::config_dir()/agent-mcr`) holds `access.json`, `history/history.md`, `read-state/` (agent workspace), and `sessions/index.sqlite` with its SQLite sidecars. Revoking session access clears the SQLite index and disables memory access.

## Key Patterns

- React functional components with hooks (no class components except ErrorBoundary)
- CSS custom properties for theming: dark by default, light overrides under `:root[data-theme='light']`; Shiki emits both themes as `--shiki-dark` / `--shiki-light` variables
- Zustand actions return `{ success: boolean; error?: string }` for operations that can fail
- Scroll handlers debounced at 50ms
- Mermaid renders lazily with strict security level
